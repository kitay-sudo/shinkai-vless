# Shinkai VLESS

Интерактивный установщик Xray **VLESS + XHTTP + Reality** для Debian/Ubuntu. Один скрипт — рабочая клиентская ссылка.

Трафик идёт в форме обычных HTTP/2-запросов (XHTTP) под маскировкой Reality — это переживает DPI и throttling, на которых умирает «голый TCP-Reality».

> **Важно про белые списки.** Если провайдер режет всё заграничное (разрешены только российские IP) — **вход должен быть на российский сервер**. Прямой коннект на заграничный IP не пройдёт, какой SNI ни ставь. В этом случае смотри [Часть 2](#часть-2--с-релеем).

| Скрипт | Что делает |
| --- | --- |
| [`install.sh`](install.sh) | VLESS + XHTTP + Reality сервер. Вход и выход — этот сервер. |
| [`install-relay.sh`](install-relay.sh) | Транзитный РФ-узел: вход на российский IP, выход на заграничный сервер. |
| [`uninstall.sh`](uninstall.sh) | Полное удаление одной командой. |

---

## Часть 1 — без релея (один сервер)

Клиент коннектится прямо на сервер, оттуда выходит в интернет.

```text
клиент → сервер → интернет
```

**Куда ставить:** если провайдер режет заграницу — на **российский** VPS (напр. Selectel): вход на белый РФ-IP пропускают, выход из рос. датацентра свободный. Если провайдер не блокирует по IP — можно на любой заграничный.

```bash
curl -sSL https://raw.githubusercontent.com/kitay-sudo/shinkai-vless/main/install.sh | sudo bash -s -- SERVER_IP SNI
```

- `SERVER_IP` — IP сервера (домен не нужен, Reality ворует чужой SNI).
- `SNI` — домен-маска: **российскому** серверу → российский (`ozon.ru`, `yastatic.net`); **заграничному** → гео-согласованный (`www.microsoft.com`). Домен должен поддерживать TLS 1.3 + HTTP/2.

Без аргументов скрипт спросит всё интерактивно. Порт по умолчанию `443` (занят — задай `VLESS_PORT=8443`).

Готовая ссылка и ключи:

```bash
cat /root/vless-config/links.txt
```

Вставляешь ссылку в клиент (v2rayNG ≥ 1.9 / Nekoray / Streisand / Hiddify) — готово.

Управление: `systemctl status xray` · `journalctl -u xray -f` · `ss -tlnp | grep 443`

## Часть 2 — с релеем (РФ-вход → заграничный выход)

Когда нужен именно **заграничный IP** (гео-контент, сайты, заблокированные на уровне страны), а провайдер режет заграницу. РФ-узел с белым IP стоит на входе и тянет на заграничный сервер.

```text
клиент → 🇷🇺 РФ-узел (белый IP) → 🌍 заграничный сервер → интернет
```

**Шаг 1.** На **заграничном** сервере — обычный `install.sh` (Часть 1), забери его ссылку:

```bash
cat /root/vless-config/links.txt
```

**Шаг 2.** На **российском** сервере запусти релей и вставь ссылку заграничного как upstream:

```bash
curl -sSL https://raw.githubusercontent.com/kitay-sudo/shinkai-vless/main/install-relay.sh | sudo bash
```

Спросит: IP РФ-узла, SNI входа (`ozon.ru`) и `vless://` заграничного сервера. На заграничном менять ничего не нужно.

**Шаг 3.** Ссылка для клиента — это ссылка **РФ-узла**:

```bash
cat /root/vless-config/relay-links.txt
```

### Два режима выхода — `vless-mode`

Переключение не меняет клиентскую ссылку:

```bash
sudo vless-mode chain    # выход через заграничный сервер
sudo vless-mode direct   # выход прямо с РФ-узла (российский IP, быстро)
sudo vless-mode status
```

### Цепочка из двух РФ-узлов

Чтобы первый РФ-хостер не видел заграничного коннекта: `клиент → РФ-узел №1 → РФ-узел №2 (другой хостинг!) → заграница`. Ставишь снизу вверх, каждый раз передавая `vless://` ссылку предыдущего узла как upstream.

## Удаление — одной командой

```bash
curl -sSL https://raw.githubusercontent.com/kitay-sudo/shinkai-vless/main/uninstall.sh | sudo bash
```

Останавливает и сносит Xray, удаляет конфиги, ключи, `vless-mode` и правила фаервола. Чужие сервисы не трогает. Запускать на каждом сервере, где ставил.

---

## Безопасность

Не публикуй UUID, private key, `vless://` ссылку и содержимое `/root/vless-config/`.
